## 🎮 Рендереры (v1.26.0 — честный статус)

- **OpenGL 3.3 core** — рабочий рендерер, используется всегда. Проверен на Windows x64/x86/arm64 и Linux.
- **Vulkan** — интерфейс и структура кода есть, **отрисовка не реализована**: функции заглушки
  возвращали «успех», ничего не рисуя. До v1.26.0 `isVulkanAvailable()` отвечала «да» по одному факту
  наличия `vulkan-1.dll` в системе (он есть почти на любом ПК с драйвером видеокарты), из-за чего окно
  создавалось с `GLFW_NO_API` — без контекста OpenGL — и пользователь получал чёрное окно без подсказок,
  а выбор `renderer=vulkan` сохранялся в `aeros_settings.ini` и ломал каждый следующий запуск.
  Теперь наличие загрузчика (`vulkanLoaderPresent()`) отделено от возможности рисовать
  (`isVulkanAvailable()`), приложение всегда работает на OpenGL, а запрос Vulkan пишет
  предупреждение в журнал и в отладочный отчёт.
- CLI: `--vulkan`, `--opengl`, `--help` (запрос Vulkan логируется и приводит к OpenGL)
- Настройки: `aeros_settings.ini` `renderer=auto|opengl`. Запись перезаписывает настройку, а не
  дописывает строку: раньше файл открывался в режиме append, а при запуске читалась первая найденная
  запись, поэтому повторный выбор рендерера молча не применялся.
- UI: секция «Рендерер — Vulkan + OpenGL» — текущий рендерер, статус загрузчика и честная подпись.

## ⏱ Режим вычислений: таймлапс физики (NEW v1.26.0)

Физику нельзя отмотать назад — поэтому она записывается. Режим отвечает на вопросы
«что именно происходило в расчёте», «когда он развалился» и «как развивалось обтекание».

| Действие | Как |
|---|---|
| Запись истории | **F7** (или панель «Режим вычислений: таймлапс физики») |
| Просмотр / пауза | **F8** |
| Окно с графиками и полем | открывается автоматически при F7/F8, галочка «Показывать окно таймлапса» |
| Экспорт истории | кнопка «Экспорт CSV» → `logs\timelapse-<дата>.csv` (39 колонок) |
| Автоматически при выходе | если включён режим отладки (F9), история выгружается сама |
| Сводка в отчёте | **F10** — сводка таймлапса входит в `Aeros-Debug-Report-<дата>.txt` |
| Из командной строки | `--timelapse`, `--no-timelapse`, `--timelapse-capacity N`, `--timelapse-field N`, `--timelapse-speed X` |

**Что пишется:** каждый кадр — время, dt, FPS, бэкенд (CUDA/CPU), число частиц и линий тока,
шаг LBM, rho, vmax, TKE, Reynolds, векторы подъёмной силы / сопротивления / момента, центр
давления, времена шести подсистем, счётчик NaN/Inf, остаток сходимости LBM, диапазон Cp.
Каждый 30-й кадр — снимок поля давления `24^3` (работает и без LBM: Cp считается по Бернулли).

**Что показывается:** 10 графиков истории с курсором воспроизведения (FPS, время кадра, время
LBM, подъёмная, сопротивление, TKE, остаток сходимости, vmax, частицы, счётчик NaN/Inf) и три
тепловых среза записанного поля (XY, XZ, YZ) в той же цветовой схеме и диапазоне, которые
действовали в момент записи. Скорость просмотра 0.1x…32x, где 1x — реальное время записи.

**Фоновая история** включена по умолчанию: буфер-кольцо (~5 МБ) пишется постоянно, поэтому к
моменту сбоя запись уже есть. Во время просмотра буфер замораживается, чтобы кольцо не
перезаписывалось под курсором.

## 🎨 Карта давления (v1.26.0)

- Давление берётся **трилинейной интерполяцией** по сетке LBM, а не ближайшей ячейкой: карта
  больше не ступенчатая. Точки вне расчётной области больше не получают «нулевое давление»
  и не рисуются как невозмущённый поток.
- Диапазон раскраски считается **по фактическим данным** (робастно: отсечение 1% крайних
  значений, симметрия относительно нуля, сглаживание), а не зашит как `[-3, +1]`. В старом окне
  Cp = 0 попадал на 75% шкалы и рисовался оранжевым, а всё сжатие сливалось в красный.
- Схема **расходящаяся**: Cp = 0 — нейтральный серый, разрежение — синий, сжатие — жёлто-красный.
  Все четыре схемы работают (раньше «Plasma» для давления игнорировалась).
- **CPU и CUDA красят одинаково**: диапазон и номер схемы передаются в `FlowParams` и
  используются в ядре GPU. Раньше у ядра была своя зашитая шкала, и при переключении бэкенда
  модель меняла цвет.
- Вместо текстовой легенды рисуется **настоящая цветовая шкала** с отметкой нуля и подписями
  фактического диапазона; диапазон можно задать вручную (галочка «Авто-диапазон Cp»).

## 🖥 Интерфейс (NEW v1.28.0)

Компоновка как в инженерных CFD/САПР-пакетах (ANSYS Fluent, STAR-CCM+, ParaView):
панели **закреплены по краям экрана**, а 3D-вид остаётся свободным в центре и ничем
не перекрыт.

```
+-----------+---------------------------+---------------+
| Навигатор |                           |   Свойства    |
|  расчёта  |      3D-вид (viewport)    | выбранного    |
|  (дерево) |                           |    узла       |
+-----------+---------------------------+---------------+
| Консоль (журнал)  |  Мониторинг сходимости  | статус  |
+-----------------------------------------------+
```

- **Навигатор расчёта (слева).** Дерево из 7 групп и 20 узлов: «Расчёт», «Модели и среда»,
  «Сетка и решатель», «Результаты», «Мониторинг», «Вид», «Диагностика». Сверху — строка
  поиска по узлам (RU/EN, без учёта регистра). Клик по узлу показывает его настройки справа.
- **Свойства выбранного узла (справа).** В заголовке окна видно, какой узел открыт
  («Свойства — Поток и граничные условия»). Все 20 прежних разделов сохранены дословно —
  ни одна настройка не потерялась и не изменила поведение, просто каждый рисуется для
  своего узла дерева.
- **Консоль и мониторинг сходимости (внизу).** Слева — журнал событий и действий
  (ошибки красным, предупреждения жёлтым, действия голубым, физика зелёным), справа —
  три кривые сходимости из самописца (остаток RMS dρ, подъёмная сила, аномалии решателя),
  под ними **строка состояния**: итерация, остаток, бэкенд CPU/CUDA, FPS и время кадра,
  сетка LBM, ρ, vmax, диапазон Cp, подъёмная/сопротивление, Re, TKE, занятая память.
- **F12 — скрыть/показать все панели** (кнопка «Панели (F12)» тоже есть): центр экрана
  остаётся чистым видом для скриншотов и записи видео.
- **Компоновка настраивается и запоминается**: ширина навигатора (180…480 px), ширина
  свойств (320…900 px), высота нижней полосы (120…520 px), видимость каждой панели,
  масштаб интерфейса 0.80x…1.80x — всё пишется в `aeros_settings.ini`
  (`uiTreeW`, `uiPropsW`, `uiBottomH`, `uiShowTree/Props/Console`, `uiSelectedLeaf`,
  `uiDocked`, `uiScale`). На узком экране панели автоматически сжимаются, чтобы не
  занимать больше 85% ширины.
- **Быстрая панель** в одну строку под статусом: Модель (F1), Давление (F2), Линии тока (F3),
  Частицы (F4), Скриншот (F5), CSV (F6), Самописец (F7), Просмотр (F8), На всё окно (F11),
  Панели (F12), Журнал (F9), Отчёт (F10) и масштаб интерфейса.
- **Окна больше не утащить на середину вида**: позиция и размер пристыкованных панелей
  задаются каждый кадр (`NoMove|NoResize|NoCollapse|NoSavedSettings`), как у настоящих
  док-панелей. В v1.27.0 размер задавался один раз (`ImGuiCond_FirstUseEver`) — до этого
  `ImGuiCond_Once` возвращал панель в угол и к размеру 540×1150 при каждом запуске.
- **Окно самописца встаёт в свободный центр** между навигатором и свойствами, а не поверх
  них; в полноэкранном режиме (F11) занимает весь экран.
- **Самописец на всё окно (F11).** Таймлапс физики разворачивается во весь экран:
  11 графиков истории (FPS, времена подсистем, силы, TKE, остаток сходимости, vmax,
  частицы, NaN/Inf, аномалии решателя LBM) и три тепловых среза поля давления
  растягиваются по доступной площади, ползунок по кадрам — на всю ширину,
  показания кадра — таблицей. Кнопка «На всё окно» есть и в панели, и в самом окне.

## ⏱ Такт физики (NEW v1.29.0)

Физика считается с **фиксированной частотой в Гц, независимо от частоты кадров** — как
в BeamNG.drive, где физика идёт на 2000 Гц при рендере 60 к/с. Чем выше частота, тем
меньше шаг интегрирования и тем точнее и устойчивее решение.

```
частота кадров:      |----16.7 мс----|----16.7 мс----|----16.7 мс----|   (60 к/с)
такты физики 240 Гц: |-|-|-|-|-|-|-|-|-|-|-|-|-|-|-|-|-|-|-|-|-|-|-|-|   (4 такта на кадр)
шаги решётки LBM:    по накопленному модельному времени (дробный остаток переносится)
```

- **Результат больше не зависит от монитора.** Раньше за кадр делалось `stepsPerFrame`
  шагов решётки, поэтому на 144 Гц обтекание развивалось в 2.4 раза быстрее, чем на 60 Гц.
  Теперь поле течёт по модельному времени: 2 секунды реального времени — это 2 секунды
  обтекания при любой герцовке.
- **Частота настраивается**: 30…2000 Гц, пресеты 60 / 240 / 500 / 1000 / 2000 Гц
  («2000 Гц — как BeamNG»). По умолчанию 240 Гц.
- **Частицы и динамика полёта** интегрируются тем же фиксированным шагом (до 8 подшагов
  на кадр): просадка кадра больше не даёт «прыжок» частиц через половину области.
- **Шаг решётки LBM фиксирован физикой** (Δt = размер ячейки / масштаб скорости):
  поднять частоту тактов значит чаще интегрировать частицы, силы и полёт и точнее
  планировать шаги решётки, но не сделать сам шаг короче — короче шаг только мельче сетка.
  Дробный остаток шага накапливается, поэтому дрейфа на длинной дистанции нет.
- **Защита от «догонялок»**: длинный кадр (alt-tab, пауза) обрезается до 0.25 с, число
  тактов на кадр ограничено (по умолчанию 64). Если физика не успевает за реальным
  временем, это видно в строке состояния, в панели и в журнале — шаг при этом остаётся
  прежним, поэтому решение не «рвётся» (как slow motion в BeamNG).
- **Две честные метрики времени**: `timeScale` (модельное/учтённое реальное, 1.0 пока
  успеваем) и `wallScale` (против настоящих часов, с учётом сознательно пропущенного
  времени `droppedTime`).
- **Где смотреть**: узел дерева «Такт физики (Гц)» → таблица живых измерений; строка
  состояния внизу; 12-й график самописца «частота тактов физики, Гц»; колонки CSV
  `phys_hz`, `phys_achieved_hz`, `phys_ticks`, `phys_lbm_steps`, `phys_sim_time`,
  `phys_time_scale`.
- **Настройки**: `aeros_settings.ini` (`physFixed`, `physHz`, `physMaxSubsteps`,
  `physParticleSubsteps`) и ключи `--physics-hz N`, `--physics-substeps N`,
  `--fixed-physics`, `--no-fixed-physics` (прежний покадровый режим).

## 🔬 Ревизия физики (NEW v1.30.0)

Проверка шести заявленных проблем по текущему коду: пять подтвердились и исправлены,
одна (источник скорости для частиц) уже была корректной — на неё добавлен тест, чтобы
она не сломалась в будущем. Такт физики, производительность, многопоточность и путь
CUDA не изменялись.

| Проблема | Что было | Что стало |
|---|---|---|
| Единицы температуры | `T = airTemperature + 273.15f`, хотя `airTemperature` уже в кельвинах | μ = 1.789e-5 Па·с вместо 2.886e-5 (+61 %), Re = 1.92e6 вместо 1.19e6; формула одна — `airSutherlandViscosity(T_kelvin)` в `flow_field.h` |
| Равновесные популяции | `rho = clamp(rho, 0.8, 1.2)` внутри `feq` → `sum(feq) ≠ rho` | обрезки нет, масса и импульс сохраняются при ρ = 0.55…1.6 (тест) |
| Давление и Cp | `|p| > q → p = ±q` в поле; `aeroClampCp()` **перед** `-cp·q·n·area` | данные не ограничиваются, диапазон режет только карта цвета; пик давления +245 → +324.5 Па |
| TKE | постобработка писала `0.5·|ω|²·0.01 + S²·0.005` (потолок 10) вместо TKE решателя | `lbmTKEField` принадлежит модели Смагоринского (м²/с²), единицы всех полей описаны в `lbm.h` |
| Настройки-пустышки | `useMRT`, `useZouHeBC`, `useRegularized` в UI, пресетах и журнале — и ни одного чтения в решателе | переключатели заблокированы с подписью «НЕ РЕАЛИЗОВАНО», `useZouHeBC` по умолчанию `false`, пункт «Вход Zou/He» исправлен, `lbmInertSettings()` виден в панели, журнале и отчёте |
| Источник скорости | выбирался условиями внутри `computeVelocityFieldCPU()` | `aeroVelocitySourceAt()` / `aeroVelocitySourceName()` — одна точка решения для расчёта, тестов и диагностики |

**Диагностика вместо тихой подмены** — счётчики видны в панели «Решатель LBM», в строке
состояния, в журнале физики и в отладочном отчёте (F10): `rho вне [0.5;1.5]`, `rho NaN`,
`|u|>0.3 ограничено`, `p NaN`, `Cp NaN у треугольников`. Нули означают чистый расчёт;
защита от расходимости сохранена, но теперь она считается, а не происходит молча.

**Известное ограничение GPU:** ядро `updateParticlesKernel` получает только `FlowParams`
и не читает поле решателя, поэтому на GPU частицы интегрируются аналитическим полем, а на
CPU — полем LBM. Факт пишется в журнал физики; перенос поля LBM в память устройства
меняет путь CUDA и в ревизию не входил.

## 🧮 Физика LBM (v1.27.0)

- **Модель турбулентности Смагоринского заработала.** В `ν_t = (Cs·Δ)²·|S|` подставлялся
  размер ячейки в метрах, а `|S|` считается в решёточных единицах — из-за смешения единиц
  ν_t была на 2–4 порядка меньше, вклад в `τ_eff` ~1e-5, и срывные режимы считались без
  подсеточной диссипации. Теперь Δ = 1 (решёточные единицы).
- **TKE в физических единицах.** Было `Cs²·dx²·S²` (метры × решёточные единицы, сверху
  зажатое единицей) — режим «Turbulent KE» и `lbmTKE` в CSV показывали произвольные числа.
  Стало `k = (Cs·Δ·|S|)²` с переводом в м²/с² квадратом масштаба скорости V∞/U0.
- **Убраны ограничения, ломавшие сохранение массы и импульса**: обнуление отрицательных
  `feq` (при |u| ≤ 0.3 оно аналитически невозможно: худший случай даёт 0.37·w·ρ > 0,
  то есть ветвь срабатывала только на испорченных данных и нарушала Σfeq = ρ), обнуление
  отрицательных `f` после столкновения и подмена популяций при `f < −0.2` / `f > 1.0`
  (пороги задевали рабочие значения; расширены до заведомо нефизических −1…10).
- **Аномалии решателя видны**: счётчики отрицательных популяций и заменённых нефизических
  значений — в панели LBM, в самописце (график и колонки CSV) и в сводке отчёта.
- **Число Рейнольдса** считается с вязкостью по Сазерленду, как в остальном коде:
  прежняя зашитая 1.81e-5 Па·с давала Re, не совпадающий с тем, по которому считались
  коэффициенты трения (особенно на высоте).

## 🐞 Режим отладки и журнал (NEW v1.25.0)

Если что-то работает не так — включите журнал и пришлите отчёт: по нему проблему
можно разобрать удалённо, без доступа к вашему компьютеру.

**Быстро:**

| Действие | Как |
|---|---|
| Включить/выключить журнал | `F9` (или панель «Отладка и журнал», или `--debug`) |
| Сохранить отчёт | `F10` (или кнопка «Сохранить отчёт», или `--save-report`) |
| Показать журнал поверх сцены | галочка «Показывать журнал поверх сцены» / `--debug-overlay` |
| Перепроверить CUDA | кнопка «Перепроверить CUDA» в панели «Отладка и журнал» |

**Что создаётся** (в папке программы; если она только для чтения — в
`%LOCALAPPDATA%\AerosEngine` на Windows или `~/.aeros` на Linux):

- `logs\aeros-debug.log` — журнал событий: запуск, версии, железо (ОС, разрядность,
  CPU, SSE2/AVX/AVX2, память, PE-машина запущенного exe), OpenGL, состояние CUDA,
  модель, **все действия пользователя** (каждое изменение параметров — что и на какое
  значение), предупреждения и ошибки. Запись сбрасывается на диск после каждой строки,
  поэтому журнал не обрывается при падении.
- `logs\physics.csv` — журнал физики по кадрам: dt, FPS, бэкенд, число частиц и линий
  тока, шаг LBM, rho, vmax, TKE, Re, силы и моменты, времена всех подсистем и счётчик
  неконечных значений (NaN/Inf). Удобно открывать в Excel и строить графики.
- `Aeros-Debug-Report-<дата>.txt` — **единый отчёт**: всё перечисленное плюс текущие
  параметры и последние 400 строк журнала. Именно этот файл нужно присылать.

**Ключи командной строки:** `--debug`, `--debug-actions`, `--debug-physics`,
`--debug-overlay`, `--physics-every N` (строка физики каждый N-й кадр, по умолчанию 4),
`--save-report`.

**Если программа не запускается**, выполните в её папке:

```bat
main.exe --save-report
```

Отчёт создастся без окна и графики (проверка CUDA выполняется тоже), а путь к файлу
будет показан в диалоге.

**CUDA.** При старте движок выполняет пробу бэкенда: перечисляет устройства NVIDIA,
читает имя GPU, compute capability, объём памяти, версии драйвера и CUDA и реально
запускает тестовое ядро. Причина недоступности пишется по-русски в панелях
«Отладка и журнал» и «Вычисления и Экспорт», а также в отчёт: GPU не найден, драйвер
слишком старый, GPU старше Turing (нет машинного кода для этой архитектуры), GPU занят,
не хватило памяти, сборка без CUDA. При любой ошибке GPU во время расчёта движок в том
же кадре переходит на CPU-бэкенд и автоматически сохраняет отчёт.

## Сборка

### Windows
Требуется: Visual Studio 2022, CUDA Toolkit опционально, Vulkan SDK опционально (для Vulkan рендерера, иначе OpenGL fallback)
```bat
cd aeros
build.bat deps          # скачать зависимости (GLFW, GLM, GLAD, ImGui)
build.bat               # x64 Vulkan+OpenGL auto
build.bat x64           # x64
build.bat x86           # x86
build.bat vulkan        # Vulkan only
build.bat opengl        # OpenGL only
build.bat clean         # очистка
```

### Linux
```bash
cd aeros
./build-linux.sh install-deps   # системные зависимости (apt/dnf/pacman)
./build-linux.sh download-deps  # bundled (GLM, GLAD, ImGui)
./build-linux.sh check-deps     # проверка
./build-linux.sh all            # auto Vulkan+OpenGL
./build-linux.sh vulkan         # Vulkan only
./build-linux.sh opengl         # OpenGL only
./bin/aeros-engine --help

# Makefile
make -f Makefile.linux install-deps
make -f Makefile.linux all
make -f Makefile.linux package
```

### CMake (Windows и Linux)
```bash
cmake -B build -DAEROS_ENABLE_VULKAN=ON -DAEROS_DOWNLOAD_DEPS=ON
cmake --build build --config Release
# Linux
cmake -B build && cmake --build build
./build/aeros-engine --help
```

### Docker
```bash
docker build -f packaging/Dockerfile -t aeros-engine .
docker run -it --rm -e DISPLAY=$DISPLAY -v /tmp/.X11-unix:/tmp/.X11-unix aeros-engine
```

## Релизы (PC)

PC-релизы публикуются в Releases по тегу `vX.Y.Z` и собираются GitHub Actions
(`.github/workflows/pc-release.yml`) в формате прежних PC-версий:
установщики `Aeros-Engine-Setup-<arch>-vX.Y.Z.exe`, апдейтеры
`Aeros-Engine-Update-<arch>-vX.Y.Z.exe` и портативные
`Aeros-Engine-Portable-<arch>-vX.Y.Z.zip` для x64 / x86 / arm64,
плюс `SHA256SUMS.txt` и `README.md` — 11 файлов. x64 — с CUDA, x86/arm64 — CPU-сборки.

С v1.25.0 CI проверяет, что x64 действительно собран через `nvcc`: скрипты сборки
пишут маркер `aeros\bin\BUILD-BACKEND-<arch>.txt` (`CUDA` / `CPU_ONLY`), и при
маркере, отличном от `CUDA`, публикация релиза останавливается — раньше тихий
переход на CPU-only приводил к релизу с неработающей CUDA. CUDA-код собирается как
`-gencode arch=compute_75,code=[sm_75,compute_75]`: SASS для Turing плюс PTX для
более новых GPU (Ampere / Ada / Blackwell).

Локально: `aeros\build.bat [x64|x86]` (CUDA), `aeros\build-cpu.bat [x64|x86|arm64]` (CPU),
установщики — `installer\build-installers.ps1`, портативные — `installer\build-portable.ps1`
(Inno Setup 6; GLFW для x86/arm64 подтянут `tools\get-glfw-x86.ps1` / `tools\build-glfw-arm64.ps1`).
