# Headless-тесты Aeros Engine

Тесты, которые проверяют логику движка **без OpenGL, GLFW и CUDA** — их можно
запустить в любом Linux-контейнере и в CI, где нет графики.

Запуск:

```bash
cd aeros/tests
make             # все 17 наборов (1285 проверок)
make timelapse   # только таймлапс
make lbm         # только прогон решателя
make physclock   # только такт физики
make fem         # только CAD/CAE: сетка, решатели, результаты, компоновка
make ui          # только оболочка CAD/CAE: панели, меню, кнопки, клавиши
make settings    # только реестр настроек: сохранение, загрузка, сброс, профили
make vulkan      # только Vulkan-бэкенд: swapchain, режим показа, раскладка, SPIR-V, геометрия
make validate    # Cd сферы/цилиндра против эталонов, сеточная сходимость
make physref     # эталонные течения: Пуазейль, вязкость, порядок сходимости (v1.36.0)
make stl         # формат STL: хвост, обрезок, ASCII/бинарный, NaN, координаты (v1.36.0)
make voxel       # вокселизация: BVH, объём, дырки, детерминизм, план сетки (v1.36.0)
make openurl     # запуск внешних программ без shell (v1.36.0)
make bench       # НЕ проверка: замер мс/шаг и млн обновлений ячеек/с
```

Полный прогон с аннотациями для CI: `./run-suites.sh` (те же 17 наборов,
`EXTRA_CXXFLAGS` передаётся в сборку).

Все тесты возвращают код 0 при успехе и 1 при любом провале, поэтому их можно
встраивать в CI.

Две особенности `make ui`:

* Кнопки нажимаются без мыши — через `ImGui::ActivateItemByID()`. Запрос
  разбирается в `NavUpdate()` в **конце** кадра, поэтому после активации тест
  рисует два кадра: в первом активация принимается, во втором выполняется
  обработчик. Так проверяется тот же код, что и по щелчку мыши.
* Проверка нехватки памяти перезапускает тест отдельным процессом
  (`--oom-child`) с урезанным адресным пространством. В сборке с
  `-fsanitize=address` эта проверка **непоказательна** (сам ASan резервирует
  теневую память), поэтому тест сообщает об этом и не считает её провалом.

Тесты намеренно **не входят** ни в один релизный сборочный скрипт: вместо
OpenGL/GLFW/CUDA они линкуют заглушки (`updateVertexColors`, `computeLiftDrag`,
`glfwGetTime`, `setVoxelData`, `cudaConsumeError`), поэтому проверяют физику и
логику, но не отрисовку.

Опорные значения прогона LBM (сфера R = 0.7 м, V∞ = 20 м/с, сетка 24³, 120 шагов):
ρ ≈ 0.9935, Cp на критической точке ≈ +1.00 (теоретическое значение для
несжимаемого обтекания), vmax ≈ 1.13·V∞, TKE ≈ 3.9·10⁻² м²/с², отрицательных
популяций 0.

Опорные значения прогона CAD/CAE (`make fem`):

Тесты намеренно проверяют **не «дымовые» свойства, а совпадение с аналитическим
решением**, поэтому они ловят настоящие дефекты: именно так были найдены гонка
данных в конвекции (Robin-члены применялись по парам «грань–узел» в параллельном
цикле — поток занижался до −69 % и менялся от запуска к запуску), неверная
таблица узлов грани −z (нагрузка ложилась не на те узлы, пометка границы
захватывала лишний слой) и захват второго слоя узлов пресетом «грань» (условие
Дирихле вставало внутри тела, эффективная длина L − h).

Проверка детерминированности: `OMP_NUM_THREADS=1|2|4|8 make fem` — результаты
обязаны совпадать. Сборка элементов идёт по восьми цветовым группам (элементы
группы не имеют общих узлов), а Robin-члены агрегированы по узлам, поэтому
параллельная сборка не требует атомиков и не зависит от числа нитей.
